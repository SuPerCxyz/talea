## Context

当前 TUI 在 `index.Open`/迁移后创建空列表，后台执行完整 `syncer.Sync`，完成后才读取列表。索引器每次先读取全部已跟踪会话，再调用各适配器 `Discover`；OpenCode 的发现查询返回整个 `session` 表，文件适配器也会重新遍历来源目录，之后才用来源时间和大小跳过未变化会话。同步末尾还会刷新活动状态和 FTS。

本设计只改变 Talea 自己的索引、同步和 TUI 生命周期。Claude/Codex 原始 JSONL 与 OpenCode SQLite 始终以只读方式访问，不依赖 Agent watcher 或 Agent 端 API。

## Goals / Non-Goals

**Goals:**

- 有缓存时让 TUI 先可用，后台同步完成后无损刷新。
- 在 Talea 索引库中保存可恢复的来源扫描状态和 OpenCode 高水位游标。
- 无变化同步不重新发现、解析、写活动状态或扫描 FTS。
- 指纹、游标或查询出现不确定性时保守回退，优先保证不漏会话。
- 保持 Agent 数据只读、单来源容错、索引权限和现有 CLI 同步语义。

**Non-Goals:**

- 本变更不实现 JSONL 文件的尾部断点解析；`source_offset` 的完整利用留给后续变更。
- 本变更不把 Token 时间线全部延迟到详情页；时间线解析仍以现有索引能力为准。
- 不修改 Agent 数据库 schema，不创建 Agent 数据库索引，不引入常驻 watcher、网络或新依赖。
- 不改变 `talea list`、`talea go` 的同步前置行为。

## Decisions

### 1. TUI 采用缓存优先、后台刷新

启动时先从 Talea 索引读取列表，并使用数据库中已经保存的工作目录存在性、项目和 Git 字段；缓存路径不调用逐会话 Git 探测。若没有会话缓存，沿用当前加载卡片。

缓存显示后，Bubble Tea 继续运行后台同步命令。同步阶段通过现有消息通道更新“正在同步”状态；完成后重新查询列表并按会话键恢复选中项。失败时不清空旧列表，只展示过期/失败反馈。`list` 与 `go` 仍保持同步后输出，避免无交互 CLI 默默返回过期数据。

替代方案是继续阻塞 TUI 但优化同步；该方案不能消除用户等待，因此不采用。

### 2. 在 Talea 索引中保存来源扫描状态

新增本地扫描状态表，按 Agent 实例和来源根记录指纹、来源类型、可选游标和最近成功同步时间。schema 迁移沿用 `internal/index/db.go` 的幂等迁移机制；旧库首次升级时没有状态，自动走一次完整发现并建立状态。

快速探测只读取本地元数据：

- OpenCode 检查数据库主文件、WAL/SHM 文件以及路径信息；
- Claude/Codex 检查上次发现过的来源文件和父目录元数据，目录状态无法排除新增/删除时回退完整 `WalkDir`。

指纹状态只用于跳过发现，不用于推断会话内容。任何缺失、解析失败、路径变化或状态不一致都走完整发现，避免快速路径造成漏索引。

### 3. OpenCode 使用适配器专属的增量发现能力

保留基础 `Discover` 作为完整回退路径，在适配器可选能力中增加带不透明状态的增量发现。核心索引层只保存和传递通用状态，不出现 Agent 三选一分支；OpenCode 适配器负责将游标转换为 `(time_updated, session_id)` 查询。

查询使用安全时间重叠窗口，并用 `session_id` 处理同一毫秒的并列更新。成功处理后，以返回候选中的最大 `(time_updated, session_id)` 更新游标；查询失败、结果无法验证或数据库路径发生变化时丢弃快速结论并调用完整发现。候选会话仍经过现有 mtime/size 比较，未变化会话不会重新解析。

替代方案是仅依赖 OpenCode 数据库文件 mtime；它只能说明数据库变了，不能定位变化会话，因此仍会导致全量 `session` 查询，不采用。

### 4. 将同步写入变成真正幂等

活动状态 SQL 增加状态差异条件，最近活动更新也只修改状态确实变化的行。会话 upsert 标记受影响记录的 FTS 状态；FTS 同步只处理脏记录并更新现有行，而不是每次执行全表缺失行扫描。迁移后的旧会话初始标记为脏，保证已有索引不会因快速路径而缺失搜索数据。

同步器根据索引结果决定是否运行 FTS 补齐，但保留“FTS 尚未建立/不完整”检测和补齐路径。所有本地索引写入继续使用现有事务和权限策略。

### 5. 保持批量边界和错误隔离

重新解析的会话先批量补齐工作目录/Git 信息，再批量写入；这样可以复用相同目录的检查结果。单个来源快速探测或游标查询失败时仅该来源回退或保留旧索引，不阻止其他 Agent 继续同步。后台刷新使用 context，可在 TUI 退出时结束。

## Risks / Trade-offs

- [OpenCode 的 `time_updated` 可能没有可用索引] → 游标查询仍可能扫描 `session` 表，但只返回和解析变化候选；实现中保留查询耗时基准和完整发现回退。
- [文件目录元数据无法覆盖所有新增/删除场景] → 保存父目录状态；无法证明完整性时强制完整发现，而不是猜测无变化。
- [缓存列表可能短暂过期] → TUI 明确展示后台同步状态，失败时保留旧数据并标记过期；首次无缓存仍阻塞在加载态。
- [本地 schema 迁移失败或中断] → 使用现有版本备份和幂等迁移机制；不触碰 Agent 数据，失败时保留旧索引并返回错误。
- [FTS 脏状态与会话写入不一致] → 在同一索引事务中标记脏记录，FTS 补齐成功后再清除；中断后下次继续补齐。

## Migration Plan

1. 提升 Talea 索引 schema 版本，创建扫描状态和 FTS 状态所需的本地结构；旧会话首次标记为需要 FTS 补齐。
2. 首次启动执行一次兼容的完整来源发现，建立文件/数据库指纹和 OpenCode 游标。
3. 后续启动先读缓存，再使用快速探测；不确定时自动回退完整发现。
4. 若新逻辑验证失败，可通过版本化索引备份恢复旧索引；Agent 原始数据不需要迁移或回滚。

## Open Questions

无。OpenCode 时间戳字段、Agent 数据位置和只读约束已由现有格式文档与适配器实现确定；查询是否命中 Agent 自有索引只影响性能，不改变回退策略。
