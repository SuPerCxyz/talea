## Context

当前 TUI 在启动时通过后台命令调用 `syncer.Sync`，加载视图已经显示三阶段和 spinner，但阶段行主要依赖普通文本、颜色和少量加粗，缺少明确的视觉焦点。同步编排实际包含 Agent 探测、会话索引、搜索索引准备和活动状态刷新，但后台命令目前没有向 TUI 传递阶段信息。

## Goals / Non-Goals

**Goals:**

- 用固定高度的三行阶段卡表达真实同步进度。
- 让阶段更新从后台同步任务传回 Bubble Tea 主循环，避免直接并发修改 UI 模型。
- 保留现有 `Sync` 调用方和同步结果、错误语义。
- 对中文和英文提供自然且不暗示“首次加载”的文案。
- 通过卡片边框、留白、加粗和高对比度建立明确的当前阶段层级。
- 将 `Talea` 标题作为卡片视觉焦点，居中显示并与辅助文案形成层级；标题保持单行，不加入块状字模或下划线。
- 让加载卡片在宽屏保持可读最大宽度，在窄屏不横向溢出。
- 让列表底部快捷键提示在不同终端宽度下保持高对比度、完整可见并可读。

**Non-Goals:**

- 不显示估算百分比、剩余时间或虚构的 Agent 级进度。
- 不改 Web 只读页面、列表页标题、索引数据口径或同步顺序。
- 不新增依赖或引入独立加载组件。
- 不尝试修改终端真实字体字号；字号由用户终端配置决定。

## Decisions

### Use coarse real stages instead of percentage progress

同步流程只提供阶段边界，没有稳定的总工作量，因而选择三个可验证的粗粒度阶段：Agent 探测、会话同步、列表准备。阶段开始时发送一次通知；完成后由下一阶段的通知或最终列表消息推进 UI。这样不会把不可知的会话数量伪装成百分比。

### Keep progress delivery inside the existing command flow

为索引器增加可选的阶段回调，在同步编排层映射为 TUI 使用的三阶段事件。TUI 创建 Bubble Tea program 后注入 `Program.Send`，后台同步通过它向主循环发送阶段消息；未注入回调时现有 CLI 和测试调用保持原有行为。

### Render a stable three-row card

加载视图固定显示标题、三行阶段、当前阶段说明和退出提示。行状态使用完成、进行中、待处理三种视觉标记；不改变 spinner，仅将其旁边的文案绑定到当前阶段。正常列表继续使用原来的 `Talea · Agent Sessions` 标题。

### Use a constrained, high-contrast loading card

使用现有 Lipgloss 样式为阶段内容增加圆角边框、内边距和受控最大宽度，并保持整体居中。当前阶段使用加粗、高对比前景/背景和 spinner 共同强调；完成与待处理状态继续通过标记和文字表达，确保无色终端也能理解状态。卡片宽度根据终端列数收缩，不添加横向滚动。

### Center a clean loading title within the card

标题使用卡片的内容宽度进行居中对齐，并通过加粗、高对比度和留白增强视觉权重；正常加载和错误加载共用同一单行标题布局，避免两种状态跳动。删除块状字模和下划线，避免横杠堆叠造成视觉噪声。终端真实字号不由应用修改。

### Render responsive keyboard hints without truncation

继续复用 Bubble Tea key binding 提供的快捷键及本地化说明，但不直接使用默认的单行截断视图。将按键渲染为高对比度加粗标签，将说明使用清晰的次级前景色，并按终端宽度在完整提示项之间换行；列表高度同步扣除新增的 footer 行数。

## Risks / Trade-offs

- [阶段信息是粗粒度的] → 不展示不可信的百分比；当前阶段文案明确说明正在执行的用户可理解工作。
- [后台任务可能在退出后继续运行] → 保持现有后台同步生命周期与退出行为不变，本次只让消息发送在程序终止后安全成为 no-op。
- [终端颜色能力不同] → 复用现有 AdaptiveColor 与 spinner，状态含义同时由符号和文字表达。
- [真实终端无法通过程序放大字体] → 通过加粗、边框、间距和宽度约束提升视觉尺寸感，并明确不改变用户终端字体设置。
- [窄终端增加边框后可用空间减少] → 卡片使用终端宽度减去安全边距的动态宽度，并对最终渲染行做宽度测试。
- [快捷键提示增加换行后可能挤压列表] → 根据实际 footer 行数调整列表高度，并测试宽、窄窗口的完整 View 输出。
